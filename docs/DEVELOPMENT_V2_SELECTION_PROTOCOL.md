# Prospective Development Suite 2 selection protocol

Written after freezing V0.3 and before generating or screening the new pool.

The pool uses explicit algebraic/grid constructions, direct sums, and generator/local-Clifford controls, not database search. They are development inputs permanently. Do not read the existing held-out directory. Also reserve, without constructing or evaluating here, quantum Golay, five-qubit concatenation, and toric distance-five constructions as unrelated future validation families. These reservations are not claims that they pass our boundary model.

For each code, validate commutation, independent rank, and logical dimension. Compute exact Pauli distance within two million patterns or give a rigorous lower bound and constructive upper bound. The rectangular Shor construction has distance min(rows,columns): commuting errors have constant row X parity; an odd parity spans all rows, and a nontrivial Z row product spans all columns. For grid codes use exhaustive bounded checks, never a name as a certificate.

Screen X/Z logical index zero with three noisy rounds and the frozen six-member initial generator for seeds 0,1,2. This is calibration, not the final strategy comparison. Record complete spectra, certified lower bounds and mechanisms. Determine the terminal-only distance independently by physical replay of all terminal singleton effects and exhaustive binary outcome-flip support enumeration. Every terminal operation affects only its own final record; therefore one fault per selected record is minimal and attainable. Exact enumeration of this classical parity problem proves a terminal-only distance, not a full-circuit lower bound. If enumeration is interrupted, mark unresolved rather than open. A terminal witness of weight at most the initial bound excludes a task from the primary suite.

Use the maximum initial certified lower bound across calibration seeds as d_initial. Choose d_target=d_initial+1, requiring d_target<=3 (the frozen practical certification tier), d_target<=d_code lower bound, and a proved terminal-only distance >=d_target. Require zero initial target successes on calibration seeds. This is intentionally a stringent difficulty rule, not a selected percentage. Cases initially at three remain secondary because extending frozen certification to tier four is computationally different. Count incomplete spectra honestly.

Reachability pilots use only RANDOM and RESOURCE_GUIDED, matched budget 64 and seeds 6,7. A separate, predetermined generic construction tries one through four independent full-interval flags on every check, serialized/separate syndrome ancillas, and both forward and reversed interactions. It is a vocabulary reachability witness, not a trained heuristic and never an initial population for the comparison. V0.3 is not piloted for admission. No pilot outcomes may alter the frozen search. Admit only tasks with independently certified reachable target architectures. Failed pilots without a witness are UNKNOWN, not proofs of impossibility.

Select up to twelve tasks, at most two bases per code, ordering candidates by structural diversity (distinct construction families first, then code distance, CSS/non-CSS representation, k and n). At least three distinct code instances are desired. Report shared construction parents and direct sums explicitly; do not count basis tasks as independent families. Include non-CSS and k>1 only if they pass the same criteria; report diversity gaps rather than force unsuitable tasks in. Boundary-limited and too-easy tasks remain secondary.

Before the final comparison freeze the selected manifest, exact targets, file hashes, seeds, budgets and success tests in Git. Final seeds 10 through 19 do not overlap screening/pilots. Five primary strategies use identical initial populations, budget 64, fault cap 200000, spectrum cap 200000 and max weight three; all other algorithm defaults remain frozen. No code-specific operator tuning. Report evaluation and wall-clock endpoints separately. If runtime requires fewer tasks, select before comparison by deterministic diversity order and measured screening time, never strategy success.

No positive conclusion from synthetic/generator-equivalent controls alone. Any difficulty correlations are exploratory. No held-out circuit or resource information is used. Do not execute held-out codes in this task even if readiness succeeds.
